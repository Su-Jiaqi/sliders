# 用真实 xBD 严重度标签重新设计训练方案（详细设计文档）

## 0. 核心思路一句话

把 `s` 从"这一对 pre/post 图片自己内部的相对插值位置"，改造成"跨场景统一、用真实 xBD 建筑损毁标注校准过的绝对严重度刻度"。

---

## 1. 现状 vs 目标

### 现状（train/train_xbd_paired_slider.py + Eq.1/Eq.3）
- 每对训练数据 (x_pre, x_post)，`s=0` 固定对应 x_pre，`s=1` 固定对应 x_post，**不管这个场景真实损毁程度是多少**。
- z_s = z_pre + s·(z_post − z_pre)，s 在 [0,1] 任意采样，这是"这一对图片自己的"插值，跟别的场景无关。
- 端点 loss（λ_endpoint）强制 ẑ0(0)≈z_pre、ẑ0(1)≈z_post，对**所有**训练对一视同仁。
- 后果：模型从没被告知"跨场景比较"这件事，s 只是局部相对量，不是全局统一刻度。

### 目标
- `s=0` 依然固定对应"未受损"（这个假设本身没问题，pre-disaster 图片天然就是 0 损毁，可以保留）。
- **真实 post 图片对应的 s 值，改成这个场景真实的归一化严重度 `s_i = S_real_i / 3`**，不再固定为 1。
- 训练时只在 `[0, s_i]` 这个"这个场景真实覆盖到的范围"内监督该场景，`s_i` 以上的区域**依赖跨场景泛化**（因为训练集里有大量不同 `s_i` 散布在 [0,1] 各处的场景，同一个共享网络能从整体上学出"严重度沿 s 增大该怎么变化"这个通用规律，而不是靠某一个场景自己imagine超出它真实观测范围的东西）。
- 这样一来，**中间严重度不再是靠 pseudo-target 硬凑的弱监督，而是有大量真实场景的真实照片直接提供的强监督**——比如某场景 S_real=1.5/3=0.5，它的真实 post 照片本身就是 s=0.5 的真实答案，不需要造假。

## 2. 数据准备

### 2.1 已有资源，直接可用
`claudecode/data/socalfire/severity_labels.csv` 已经存在（Phase 1 就产出的），包含 `local_id, split, S_real, L_bucket` 等字段，不需要重新计算。

### 2.2 需要处理的问题：只有部分训练对有可靠 S_real
- 全量训练对：769（socalfire train）
- 有可靠 S_real 标签的：366（其余 403 对因为标注建筑数太少被 `compute_flood_severity_labels.py` 的 `min_buildings` 过滤掉了）

**决策**：先用这 366 对做新方案（干净、可信），不强行放宽过滤阈值去凑数量（放宽阈值会引入低质量标签，得不偿失）。如果后续发现 366 对不够训出稳定模型，再考虑放宽。

### 2.3 严重度分布（已实测，见上文）
0-0.5 区间占 57.7%，2.5-3.0 区间占 11.7%（连同 3.0-3.5 那个越界 bin，估计是 S_real 精度计算导致，需要检查是否有超过 3.0 的异常值），中间稀疏。**这个分布形状需要写进论文/附录，作为诚实的数据局限性说明**，不管最后训练效果如何都要提。

## 3. 训练目标重新设计

### 3.1 每个训练对的"有效范围"
对第 i 对训练数据，定义 `s_i = clip(S_real_i / 3, 0, 1)`。训练时，**对这一对数据，s 只在 [0, s_i] 内采样**（endpoint-heavy 采样策略可以保留，只是把原来的"端点"从 {0,1} 改成 {0, s_i}）。

### 3.2 pseudo-target 重新构造（替换 Eq.1）
```
z_s = z_pre + (s / s_i) · (z_post − z_pre),   for s ∈ [0, s_i]
```
当 `s_i` 很小（比如场景真实几乎没损毁，s_i≈0.02）时，这个场景能提供的训练范围极窄，退化为"几乎只监督 s≈0 附近"——这是合理的，因为这个场景真的没什么可展示的中间状态。

**边界情况**：如果 `s_i = 0`（S_real 精确为 0），这一对数据只能监督 s=0 这一个点，退化为"纯粹的 pre-disaster 锚点"，不再对 λ_endpoint 的"post"那一半有贡献。需要在代码里做除零保护。

### 3.3 端点 loss 重新设计（替换 Eq.3 里的 λ_endpoint 项）
```
L_endpoint = ||ẑ0(0) − z_pre||² + ||ẑ0(s_i) − z_post||²
```
第一项对所有对不变；第二项的"锚点位置"从固定 1 改成 s_i，且 M_z(s_i) 这个严重度图输入通道要相应地填 s_i 而不是 1（架构不用改，UNet 本来就吃一个标量severity map，只是训练时喂进去的值不同）。

### 3.4 平滑正则（λ_smooth）
保持原样，只是"相邻 s'"的采样范围也要限制在 [0, s_i] 内，避免在没有监督的区域算平滑项。

### 3.5 跨场景泛化如何起作用（重要，写进方案里让实现时心里有数）
对某个查询 s，如果对当前这一对数据 s > s_i（超出这个场景真实覆盖范围），**这一对数据对这个 s 值不提供任何直接监督**，但由于训练集里同时有其他 s_j > s（j≠i）的场景在提供真实监督，共享的网络（本来就是以 x_pre 为条件的统一模型，不是每个场景一个独立模型）能够从整体上学到"给定其他场景在这个 s 附近的真实表现，这个新场景在同样 s 下大概该长什么样"——这是深度学习里条件生成模型常见的泛化方式，不需要额外设计，但**效果好不好取决于训练集在各个 s 区间的覆盖密度**，这也是第 2.3 节分布数据要重点关注的原因。

## 4. Refiner（f0/fu/f1）重新设计

### 4.1 f0（s=0 端点）
不变。s=0 的含义（未受损）跟场景无关，天然统一，不需要改。

### 4.2 f1（原来的"s=1 端点"，带语义教师 ψ 监督）
**需要重新定位**：ψ 判断"这是不是 post-disaster 类别图片"这件事，跟具体严重度无关（哪怕只损毁 10%，也依然是"post"类别，不是"pre"类别），所以 Eq.6 的分类/特征匹配 loss 本身不用改。

需要改的是：**训练 f1 时用哪些样本**。原来是"每一对的 post 图都用来训 f1"；现在建议：**只用 s_i 较高（比如 S_real ≥ 2.0，真正接近'严重'的场景）的那部分样本来训练 f1 分支**，因为 f1 在推理时依然是服务于"用户请求 s=1，即最大严重度"这个场景，应该用训练集里"真正严重"的样本去教它"最大严重度长什么样"，而不是被那 57.7% 的"几乎没损毁"样本拉偏。

### 4.3 fu（中间尺度 refiner）
用重新构造的 pseudo-target y_u(s) = D(z_s)（3.2 节的新公式）训练，覆盖每个场景各自的 [0, s_i] 范围。这是这次改动里**信息量提升最大**的部分——之前 fu 的中间监督全靠"weak pseudo-target"，现在很大一部分中间监督来自其他场景的真实照片。

---

## 5. 推理协议

**不变**。用户依然是给一张 pre 图 + 一个 s∈[0,1]，拿到对应严重度的输出。这次改动只发生在训练阶段怎么构造监督信号，推理接口、分支选择规则（s=0→f0, s=1→f1, 中间→fu）都不用动。

---

## 6. 训练规模与预估资源

- 生成模块重训：和 λ_smooth 消融同规模（15000 步，约 2-3 小时/GPU，具体取决于共享 GPU 的空闲程度）。
- f0：不用动，复用现有 checkpoint。
- fu：需要重训（用新 pseudo-target），规模和这次 λ_smooth 消融里跑的 fu 差不多（20 epoch，几十分钟量级）。
- f1：需要重训（换训练样本子集），规模类似 f1 之前的重训（~15-20 分钟）。
- 总计预估：**4-6 小时**（含推理+评测），如果 GPU 排队/共享严重可能更长。

---

## 7. 评测计划

1. 重跑 scene-level calibration（experiment_a/b），对比新旧模型在**中间 s（0.25-0.75）**的 ρ 和一致性——这是这次改动要验证的核心假设：中间严重度校准应该显著改善。
2. 重跑 Table 7/8/9 风格的多尺度 CAS 趋势，确认"总体单调上升"这个已有优点没有被破坏。
3. 用同样的 naive-interpolation 对照实验（已有 infra）重新跑一遍，看新模型是不是比旧模型在这个对照实验里赢得更明显（如果赢得更明显，说明这次改动确实增强了 s 条件生成的价值，是个很好的佐证）。
4. 检查生成图像质量（LPIPS/SSIM/PSNR/FID）有没有退化——毕竟这是个训练信号的大改动，需要确认没有把其他已经验证过的优点搞坏。

---

## 8. 风险与需要老实承认的局限

1. **中间严重度样本稀疏**（0.5-2.5 区间只占 25%）：跨场景泛化的效果上限取决于这个密度，可能中间效果提升有限，需要如实报告，不要过度期待。
2. **有效训练对从 769 降到 366**（因为要求可靠 S_real 标签）：训练数据量接近减半，可能影响生成质量，需要在评测里专门检查。
3. **外推问题**：对 s_i 很小的场景（那 57.7%），查询 s > s_i 时完全依赖跨场景泛化，没有这个场景自己的任何直接监督，效果不确定，需要用评测数据说话，不能只凭理论期待。
4. **f1 训练样本子集的阈值怎么定**（S_real≥2.0 只是个初始建议，需要根据实际数据分布调整，可能要做一次敏感性检查）。
5. **这是对训练方法论的实质性改动**，如果效果不如预期（比如中间校准没有明显改善），也是一个有价值的诚实发现，不代表方案设计错了——可能说明 xBD 这批数据的中间严重度样本密度本来就不够支撑这种做法，这本身也是值得写进论文 Limitations 的洞察。
